# Scan3D LiDAR

The Camera Studio review now adds supported ARKit high-resolution still capture, exact-frame luminance checks, rotational stability, confidence/edge-filtered LiDAR, bounded voxel averaging and a redesigned native capture UI. The shared depth-buffer adapter is tested from real synthetic CoreVideo maps through calibration and world transforms to a persisted PLY roundtrip. Reaching the point budget no longer discards later refinements of existing voxels. See `docs/CAMERA_STUDIO_DA.md` for the implemented behavior, test gates and unverified physical-camera limits. Native UI fixtures are synthetic, isolated and DEBUG-only; they are not physical sensor evidence. No megapixel, accuracy or physical performance claim is implied by CI.

Native LiDAR-capable iPhone prototype using SwiftUI, ARKit, RealityKit, MetalKit and Vision (iOS 17+; physical acceptance target: iPhone 14 Pro Max). Ordinary iPhone 13 has no LiDAR and cannot use this capture path. The source captures guided photos and camera video, samples real LiDAR depth and exports PLY/OBJ. A separate MetalKit viewer opens those saved exports without another RealityKit scene. Photo/video-based reconstruction remains planned.

Open Mine scanninger, select a project, then Se seneste punktsky i 3D or an exported PLY/OBJ. The Result screen links to its latest saved geometry. The viewer checks the exact file bytes against the stored size and SHA-256 before decoding, loads off the main thread, and never starts another camera session. Drag/pinch, accessible rotate/zoom buttons, reset and light background operate on a display copy. Source coordinates remain in meters. Displayed dimensions are approximate AR-axis extents, not precision measurements. Point clouds use small markers and at most 20,000 sampled display points; they are not reconstructed surfaces. The original export remains intact and shareable. Meshes retain their actual triangles and holes, with no automatic segmentation, texture or print repair.

This reader deliberately accepts only the app's ASCII XYZ PLY and triangle-only OBJ without materials. It rejects malformed/nonfinite coordinates, invalid or degenerate faces, unsupported external resources, empty geometry and files above 32 MiB. Limits are 480,000 vertices and 160,000 triangles. This is not an arbitrary 3D-file importer. Regression tests use the real exporters, malformed input, display bounds and camera limits. Native UI tests now open the real renderer with an isolated synthetic saved OBJ, exercise buttons and gestures, and attach screenshots. Current-revision results are in Actions. Full VoiceOver use and physical iPhone performance still require device testing.

Automatic photos are enabled by default after locking a target. An uncovered position must pass tracking, distance, aiming, translation/rotation stability, recent luminance analysis, autofocus-settling and confidence-supported depth checks; the exact delivered frame is revalidated before capture. Luminance/detail thresholds are heuristics, not calibrated focus or exposure measurements. Retakes remain manual. A save error disables automatic capture. Backgrounding, sheets and interruptions suspend capture. Resume after a paused camera requires a new target/project rather than assuming the old world coordinates are valid. Permission denial and camera interruption have explicit recovery guidance.

Mine scanninger opens persistent projects, photo thumbnails, full photos, file integrity checks and individual photo/PLY/OBJ sharing. Assets and SHA-256 records are written before an atomic manifest commit. Retakes preserve originals. Each accepted photo persists the current point cloud; this protects geometry from a later reset. JPEG/thumbnail encoding and capture file writes run on a serial background queue. The library reopens saved data read-only; it does not resume an old AR mission. It does not yet archive/import an entire project. Old Scan3DPhotos/Scan3DLiDARExports folders remain intact and accessible through Files.

Video starts automatically with a new locked target unless disabled in capture options; manual Start/Stop remains available. The recorder consumes the existing AR camera stream, never starts a second camera session and records no microphone/audio or UI overlays. It encodes H.264 in MOV, at most 1280 pixels on the long edge and 15 accepted frames/sec, preserving source aspect ratio without upscaling. Orientation is fixed at recording start. Backpressure drops frames with only one source buffer in flight. Stop, camera pause, sheets/inactive app and AR interruption request finalization; serious/critical thermal state, less than 200 MiB free storage and 5 minutes also stop the clip. These hardware/resource callbacks still require physical testing.

The project manifest journals a pending clip before recording. Only a finalized, readable video with a decoded frame is published to the library; hashing uses 1 MiB chunks. Completed clips can be played and shared. Interrupted/pending clips stay visible and can be checked for recovery. Recovery can register an already playable file after an interrupted manifest write; it cannot repair a truncated or unfinalized movie, and originals are never deleted. Old v1 manifests without video fields still load. A finite iOS background task attempts finalization; iOS may still terminate the app, leaving a pending clip. Video is not yet used to create a 3D model.

CI additionally writes synthetic frames through the actual AVAssetWriter pipeline and decodes every resulting frame. It tests timestamps, all four track rotations, no audio, resolution bounds, stop idempotence, low-space finalization, an interruption stop reason, empty/corrupt files, publication failure and recovery. These are real codec/filesystem tests on macOS, not recordings of a physical iPhone or an interactive Simulator UI test.

The source lives directly in `Scan3DLiDAR/`. CI pins Xcode 26.3 and an iOS 26.2 Simulator on the standard macOS 15 Apple Silicon runner, records the actual host/toolchain/SDK/runtime in its evidence, and compiles both Simulator and unsigned iPhone Release. macOS 26 arm64 could not acquire a host, and the Intel fallback crashed in RealityKit's texture manager while constructing the Debug test fixture. No application code or rendering test has been weakened to accommodate that host. The selected image and toolchain are documented in GitHub's official runner inventory. CI does not download an external source ZIP and runs for pull requests and pushes to main, avoiding duplicate branch/PR builds. See the current review checks; historical passes do not approve a new revision. Physical iPhone installation, signing and LiDAR acceptance tests remain outstanding.

For Mac: install Xcode and XcodeGen, run `xcodegen generate` inside `Scan3DLiDAR`, then open the generated Xcode project. Sign with your own Apple team to run on a physical supported device. An unsigned Simulator build does not install on an iPhone.

The review CI also prepares `scan3d-unsigned-iphone`: the actual Release iPhone app in an IPA plus `SCAN3D_PACKAGE.json`. The packager rejects Simulator binaries, other bundle identifiers, embedded provisioning/signing files and truncated Mach-O headers. It checks the arm64 iOS device platform, ZIP readback and SHA-256 for every file. CI explicitly checks out the review head and records that exact source commit. The IPA has no Apple provisioning and cannot be installed as-is.

For Windows with a free Apple account, AltStore Classic documents local signing through AltServer. This is a possible installation route, not a verified Scan3D installation. It needs initial Windows/iPhone setup and app refresh within the free account's seven-day period; AltStore itself uses one of three active app slots. See the official [Windows setup](https://faq.altstore.io/altstore-classic/how-to-install-altstore-windows) and [refresh limitations](https://faq.altstore.io/altstore-classic/your-altstore). The user handles Apple-account sign-in and device trust; this repository neither collects credentials nor installs signing tools automatically. Native LiDAR support and physical acceptance remain required.

The maintained app plan is `docs/APPPLAN_DA.md`, included automatically by the registered local GitHub Flow profile. No per-update ZIP download or manual GitHub upload is needed.

## Separate Safari web review

`web/safari-mvp/` contains a separate local-first photo/project and OBJ/PLY viewer app. Run `node web/safari-mvp/tools/serve.mjs`; see [the Danish Safari guide](docs/SAFARI_WEB_DA.md) for storage, export, tests and limitations. It does not provide LiDAR/ARKit or photo-to-3D reconstruction. The native app, its tests and its workflow remain separate. This branch does not deploy or release either app.

## Native LiDAR og Safari

Den native scanner kan automatisk klargøre en kontrolleret modelkopi til Safari-projektimport. Se [iPhone-forløb, test og begrænsninger](docs/LIDAR_SAFARI_DA.md). Safari får ikke direkte LiDAR-adgang.

## Chrome og iPhone-dybde · separat review

Webversionen er nu rettet mod Chrome. Den bevarer eksisterende projekter og native modelimport. På Windows starter `web/safari-mvp/Start-Chrome-LiDAR.ps1` en lokal loopback-server og åbner Chrome, når serveren er klar. Et frivilligt Record3D-modul kan modtage lokal RGBD-video og gemme et enkelt dybdeudsnit som en ny PLY-punktsky. Record3D kræver Wi-Fi-tilkøb på telefonen og en anden enhed som modtager. Sensoridentitet og rigtig telefonforbindelse er ikke verificeret; modulet er ikke en direkte LiDAR-API i Chrome eller en komplet objektrekonstruktion.

Se [opsætning, protokol og testgrænser](docs/CHROME_LIDAR_DA.md) samt [løbende native brug og iOS 27.0.1](docs/IPHONE_CONTINUOUS_USE_DA.md). SideStore er kun en undersøgt kandidat til fornyelse på telefonen. Der er ikke signeret, købt, installeret, merget eller deployet noget i denne reviewgren. Den eksisterende native projektkopi, som knappen stadig kalder Safari, kan også importeres i Chrome; format og native kildekode er bevaret.
